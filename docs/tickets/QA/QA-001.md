# QA-001 — Backend test suite

**Type:** Testing
**Epic:** QA — Testing & CI
**Affects:** `backend/`
**Priority:** P1
**Status:** `PLANNED`

## Summary
The backend has **zero** tests. `pyproject.toml` declares no test dependencies, there is no test
directory, and nothing verifies the analysis path, the validation rules, or the error contract.

## Current behaviour
No `pytest`, no `httpx`/`TestClient` usage, no fixtures, no coverage configuration. Every change to
the analyzer, the schemas, or the guard is unverified, and the only way to check anything is a live
call that costs money.

This is the hardest blocker after BE-001: without tests, none of the other tickets in this backlog
can be verified as done, and every refactor (EXT-008, MOB-001) is done blind.

## Why it matters
"I have tests, here is the coverage, here is what they prove" is the most credible sentence you can
say about a project. It also makes every other ticket here checkable, which is why it is P1 despite
being invisible in the UI.

## Proposed scope
- Add `pytest`, `pytest-asyncio`, `httpx`, and `pytest-cov` as dev dependencies (uv
  `[dependency-groups]` or `[tool.uv]` dev group).
- Add `backend/tests/` with a `conftest.py` that:
  - stubs the DeepSeek client and the TypeSafe guard so **no test ever makes a paid call**;
  - sets dummy environment variables so modules import without real keys (BE-007);
  - provides a `TestClient` fixture.
- **Unit tests** for the analyzer: valid JSON passes through; malformed JSON is handled (BE-002);
  out-of-range score is clamped; guard rejection returns 400.
- **Unit tests** for validation: empty text, oversized text, extra keys, whitespace-only input
  (BE-004).
- **Unit tests** for the guard: both CV and job text are checked; unavailable guard follows the
  documented policy (BE-008).
- **Endpoint tests** for the HTTP contract: happy path, 422, 413, 429, 502 shapes (BE-002/BE-005).
- Assert the model client is **not** called for requests rejected at validation — a cheap test that
  directly proves the cost guard works.
- Configure coverage with a threshold on the core modules (start at 80% for `services/` and
  `schemas/`, do not chase a global number).
- Document how to run the suite in `backend/README.md`.

## Acceptance criteria
- [ ] `uv run pytest` passes from a clean checkout with no API keys present.
- [ ] No test performs a real network call to DeepSeek or TypeSafe.
- [ ] Coverage is reported and a threshold is enforced.
- [ ] The tests listed above exist and fail if the corresponding fix is reverted (verify by
      temporarily reverting one).
- [ ] Runtime is under ~30 seconds so CI stays fast.
- [ ] README documents the test command.

## Notes
Useful practice: for each P1 fix in this backlog, write the failing test first. "I fixed a bug and
added the test that would have caught it" is a much stronger interview story than either half alone.
