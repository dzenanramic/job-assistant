# QA-001 — Replace placeholder tests with meaningful unit + e2e coverage

**Type:** Testing / Backend
**Epic:** QA — Testing & CI/CD
**Affects:** `backend/`
**Priority:** P1

## Summary
The only tests are scaffold `should be defined` placeholders (`*.controller.spec.ts`),
`app.controller.spec.ts` is boilerplate, and there is **no e2e test** for the AI path. There is
almost no protection against regressions. This is the single highest-value ticket for interviews:
real test coverage proves you can ship safely.

## Proposed scope
- **Unit tests** for the service in isolation: mock the OpenAI client; assert the prompt shape
  (job/CV fenced, system message separation per SEC-001), input-size guard (SEC-003), and result
  parsing (DATA-002).
- **Unit tests** for the DTO validation rules (SEC-002).
- **e2e tests** (`test/jest-e2e.json`): boot the app against a stubbed DeepSeek client and assert
  the HTTP contract for happy path + validation errors + error mapping (OBS-002).
- Wire coverage reporting; set a coverage threshold (e.g. ≥ 80% on core service/validation).
- Keep the CI in QA-002 running these on every push.

## Acceptance criteria
- [ ] `npm test` runs meaningful tests (not placeholders) for service, validation, parsing.
- [ ] `npm run test:e2e` exercises the HTTP layer for success + failure paths.
- [ ] A stubbed/mocked AI provider is used so tests run offline and fast.
- [ ] Coverage is reported and tracked.

## Notes / CV value
Recruiters and interviewers treat "tested" versus "untested" resumes very differently. This ticket
is the highest-leverage piece for the CV. Pairs with SEC-006 (red-team suite) and QA-002 (CI).
