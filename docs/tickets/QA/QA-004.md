# QA-004 — Extension tests

**Type:** Testing
**Epic:** QA — Testing & CI
**Affects:** `extension/`
**Priority:** P3
**Status:** `PLANNED`

## Summary
The extension has no tests. The pure logic — text normalization, PDF extraction, rendering — is
testable today with no browser, but nothing exercises it.

## Current behaviour
`package.json` has a placeholder `test` script (`echo "Error: no test specified" && exit 1`). The
extension's logic is split between pure functions and Chrome APIs, and some of it is genuinely
well-suited to testing:

- `normalizeText(text, site)` in `text-utils.js` — pure, deterministic, and currently throws on an
  unknown site (EXT-004).
- `extractPdfText(file)` in `file-utils.js` — pure given a fixture PDF.
- The rendering in `popup.js` — pure given a result object (EXT-002).

The blocker is structural: Chrome APIs are called at module scope and DOM elements are looked up on
import, so `popup.js` cannot be imported in a test process.

## Why it matters
Lower priority than backend tests because the extension is harder to test and has less critical
logic — but `normalizeText` is exactly the kind of function where a unit test pays for itself, and
an untested marker table is how the silent whole-page-extraction bug (EXT-004) went unnoticed.

## Proposed scope
- Add **Vitest** (or Node's built-in test runner) with `jsdom` for DOM-dependent code.
- Refactor for testability: move DOM lookups inside functions, and isolate `chrome.*` calls behind
  a thin module that can be stubbed. Do not test Chrome itself — test your logic.
- Tests against **saved HTML fixtures** for each supported site, asserting that extraction returns
  the expected job description and excludes nav/footer content. Save the fixtures from real pages.
- Tests for `normalizeText`: known site, unknown site (must not throw), marker missing (must not
  silently return the whole page).
- A PDF fixture test for `extractPdfText`, including a scanned/image-only PDF asserting the empty
  result is detected (EXT-001).
- A rendering test feeding `<img src=x onerror=alert(1)>` and asserting the output is inert text
  (EXT-002).
- Wire into the CI workflow (QA-002) and add a `lint` script (EXT-007).
- Note that the adapters in EXT-008 should be built against these fixtures from the start.

## Acceptance criteria
- [ ] `npm test` runs real tests and exits non-zero on failure.
- [ ] `normalizeText` is covered for known, unknown, and marker-missing cases.
- [ ] At least one HTML fixture per supported site asserts the extracted text.
- [ ] A PDF fixture is parsed and its text asserted.
- [ ] The XSS rendering case is covered.
- [ ] Tests run in CI.
- [ ] `chrome.*` is stubbed, not required.

## Notes
Some refactoring is a prerequisite — modules that do DOM lookups and Chrome calls at import time
cannot be tested. That refactor is worth doing on its own merits; testability here is a symptom of
the coupling, not a separate problem.
