# QA-002 — CI/CD pipeline (lint + test + build on every push)

**Type:** DevOps / CI
**Epic:** QA — Testing & CI/CD
**Affects:** repo-level (`.github/` or equivalent)
**Priority:** P2

## Summary
No automated pipeline exists; the project is only run locally. Adding CI is a classic "production
readiness" signal and demonstrates Git/GitHub fluency — a must-have for a CV project.

## Proposed scope
- Add a CI workflow (GitHub Actions or the equivalent for your host) that runs on push/PR:
  - Lint (`npm run lint`) with eslint.
  - `npm run build` (type-check + compile).
  - `npm test` and `npm run test:e2e` (with mocked AI — QA-001).
- Add a build/validate step for the extension (manifest validity / bundling if applicable).
- Optionally add a **deploy** job later (OBS/DATA final): build image, run migrations, health-check.

## Acceptance criteria
- [ ] A PR/push triggers lint + build + unit + e2e pipeline.
- [ ] The pipeline fails the merge on red checks.
- [ ] CI is reproducible on a clean checkout (documented setup steps).
- [ ] Green pipeline badge/link visible in the README.

## Notes / CV value
"Set up CI/CD, tests run automatically, main stays green" reads extremely well. Also unblocks
safe contributions and demos.
