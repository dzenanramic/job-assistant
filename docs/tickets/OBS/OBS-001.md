# OBS-001 — Structured logging & request correlation

**Type:** Observability / Backend feature
**Epic:** OBS — Observability, logging, errors
**Affects:** `backend/`
**Priority:** P2

## Summary
Logging is currently `console.log(prompt)` / `console.log(answer)` in `jobs.service.ts` — **the
full prompt and AI response get printed to stdout**, which is verbose, leaks scraps of PII/CV data
in logs, and gives no request correlation. Replace with structured, sanitized logging.

## Proposed scope
- Introduce a **logging module** (NestJS Logger or Pino) with structured JSON output and levels.
- Add a **request correlation/trace id** propagated per analysis request (id generated on POST and
  echoed in logs and returned headers), so one failure is traceable across queues (PERF-002) and DB.
- **Never log the full untrusted prompt/response** verbatim; log lengths, token usage, latency,
  score, status, trace id. Redact before logging if any content is logged.
- Dogfood: log model latency + errors from the OpenAI call.

## Acceptance criteria
- [ ] Service logs effective fields (trace id, duration, token usage, status) as structured JSON.
- [ ] Full raw prompt/CV is not emitted to stdout (verified).
- [ ] Errors carry the trace id so support/interview demos can follow a failure.

## Notes / CV value
"Structured logging + correlation IDs + no-PII-in-logs" is a genuine production habit.
