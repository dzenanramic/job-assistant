# MS-001 — Abstract multi-site job-ad extraction engine

**Type:** Epic / Feature
**Epic:** MS — Multi-site support
**Affects:** `extension/`
**Priority:** P1 (explicit ask)

## Summary
Replace the single hardcoded text-scrape-and-marker approach (currently `document.body.innerText`
trimmed at the literal string "prijavi se") with an **extensible per-site extraction engine** so
the extension produces a clean, structured job posting from **any** job board, not just the one
Bosnian/regional site it currently targets.

## Background / Why
Today `extension/chrome-utils.js` returns the whole `body.innerText` and `text-utils.js` cuts
everything after the literal substring `"prijavi se"`. This only works on tests where "prijavi se"
is literally present; on every other job board the extracted text is polluted with navbars,
sidebar links, cookie banners and unrelated content — which degrades the AI analysis quality.

## Proposed design (scope only — no implementation requested)
- Introduce an **`extraction strategy`** abstraction: a `SiteAdapter` interface
  (`id`, `matchUrls[]` or `hostnameMatcher`, `extract(pageDocument) -> JobListing`).
- Ship a small registry of adapters keyed by hostname, with a **generic/fallback adapter** for
  unknown sites (best-effort `main`/`article`/`[itemprop]` scrape) so the extension still works
  everywhere.
- The adapter should return a **structured JobListing** `{ title, company, location, seniority,
  description, postedAt, rawUrl }` so the backend can analyze a clean payload instead of one
  giant text blob.
- Apply the fallback only when no site adapter matches; log which adapter (or fallback) was used.

## Acceptance criteria
- [ ] Extension detects the current site and routes extraction through the matching adapter.
- [ ] ≥ 3 popular job boards get dedicated adapters (e.g. LinkedIn, Indeed, a local Balkan board).
- [ ] Unknown sites gracefully fall back to a generic scraper without erroring.
- [ ] Extracted output is a structured object with typed fields, not the raw `innerText`.
- [ ] No change in behaviour when no adapter matches (non-breaking fallback).

## Out of scope
- Backend changes (covered by DATA/MS tickets).
- Writing the extraction logic — that is the implementation owner's job.

## Notes for the handover / CV talking point
This ticket is the flagship "I designed a plugin/extensible architecture" story: adapter pattern +
registry + fallback. Interviewers love it.
