# EXT-002 — Configurable backend URL + robust request/error handling

**Type:** Extension feature
**Epic:** EXT — Extension UX robustness
**Affects:** `extension/`
**Priority:** P2

## Summary
`API_URL` is **hardcoded** to `http://localhost:3000/jobs` in `api.js`, and errors surface as raw
`error.message`. There's no way to point the extension at a hosted backend, no retry, and no
timeout control. This blocks the extension from ever talking to a deployed API (required once the
backend is hosted — MS/DATA/QA).

## Proposed scope
- Make the **backend URL configurable** via the extension's `chrome.storage` (an options/"settings"
  state exposed in the popup) with a sensible default; validate the URL.
- Send the auth credential from SEC-005 (API key from storage) in headers.
- Add **timeout** handling (AbortController) and a friendly "please try again" retry path.
- Surface structured errors (OBS-002 code + message) rather than raw `Error: ...`.
- Keep a mock/offline fallback so demos work without the backend running.

## Acceptance criteria
- [ ] Backend URL and key are configurable from the popup without editing code.
- [ ] Requests fail with a clear timeout/network message, not a raw stack string.
- [ ] Credential header is attached when configured (SEC-005).
- [ ] Works against both `localhost` and a deployed HTTPS URL.

## Notes / CV value
"Configurable, well-error-handled browser front-end" plus connection to real infra. Pairs with
OBS-002 error contract and SEC-005 auth.
