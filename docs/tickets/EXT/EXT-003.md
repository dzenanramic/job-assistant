# EXT-003 — Loading, progress, and empty-state UX polish

**Type:** Extension UI
**Epic:** EXT — Extension UX robustness
**Affects:** `extension/`
**Priority:** P3

## Summary
The popup is functional but rough on state handling: only one spinner string, no clear state for
"no CV selected", no error-context UI, no way to rerun, and result rendering assumes a single
paragraph. Polish the interaction model so it demonstrates intentional UX.

## Proposed scope
- Distinguish states explicitly: **idle → uploading/extracting → analysing → result | error | empty**
  (an enum in JS); render specific UI per state (see PERF-002 for async progress while polling).
- Show clear messaging when no CV is attached before analysis.
- Render structured results (DATA-002) with a **score badge**, copyable output, and a "re-run"
  action.
- Add accessible labels/ARIA (already partially there) and keyboard-friendly controls.

## Acceptance criteria
- [ ] Each state renders distinct, correct UI; no stuck spinner.
- [ ] Analysis without a CV shows a clear prompt instead of silently proceeding.
- [ ] Result section shows score + sections when structured output is available (DATA-002).
- [ ] Rerun and clear actions work without a full reload of the panel.

## Notes
A polished UI is a subtle but real CV asset ("I shipped a clean browser-extension feature"). Pairs
with PERF-002 (async) and DATA-002/003 (structured results, history).
