# EXT-001 — Close the DOC/DOCX parsing gap + file validation

**Type:** Bug / Extension feature
**Epic:** EXT — Extension UX robustness
**Affects:** `extension/`
**Priority:** P1 (claimed-but-missing functionality)

## Summary
The UI advertises **"Supported formats: PDF, DOC, DOCX"** (`popup.html`), the file input
accepts `.pdf,.doc,.docx`, but **only PDF is actually parsed** (`file-utils.js` uses pdf.js).
Selecting a `.doc`/`.docx` file silently yields nothing usable. Either implement DOC/DOCX parsing
or clearly narrow the supported formats — never advertise what isn't shipped.

## Proposed scope
- Implement **DOCX parsing** (docx is a zip of XML — parseable without heavy deps) and add **DOC**
  support or explicitly exclude DOC with a friendly message.
- Validate the file **type and size** on selection (reject non-CV files, over-large files per
  SEC-003); clear error text in the popup.
- Center handling on the `file` object (fix any `.files[0]` re-read issues; keep state consistent
  between `cvText` and the UI label).

## Acceptance criteria
- [ ] Selecting a `.docx` extracts its text successfully (unit tested with a fixture in QA-003).
- [ ] Unsupported or oversize files show a clear error and are not sent.
- [ ] Supported-format text in the UI matches what is actually implemented (no false advertising).

## Notes / CV value
Honest scope + one more concrete file-format-parsing capability. Ties into QA-003 fixtures.
