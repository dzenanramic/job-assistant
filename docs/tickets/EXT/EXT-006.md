# EXT-006 — Re-analyze without re-uploading the CV

**Type:** UX / Feature
**Epic:** EXT — Extension robustness
**Affects:** `extension/popup.js`
**Priority:** P2
**Status:** `PLANNED`

## Summary
The parsed CV lives only in a JavaScript variable inside the side panel. Closing the panel — or the
browser deciding to unload it — discards it, and the user must find and upload the PDF again.

## Current behaviour
```javascript
let cvText = "";
```

Nothing persists it. Chrome side panels are unloaded when closed, so `cvText` resets to `""` on
every reopen while the UI still looks like a fresh start. The realistic user flow is exactly the
one this breaks: open a job ad → analyze → open the next job ad → analyze again. Today that means
re-uploading the CV for every job.

There is also vestigial state handling: the `// cvInput.value = "";` line is commented out, which
is the reason re-selecting the same file does not fire `change` (see EXT-001), and the panel shows
"CV added ✓" with no way to see the text that was actually extracted.

## Why it matters
This is the difference between "a demo" and "something I would actually use." For a portfolio
project, the flow a reviewer performs is: analyse several job ads in a row. Making that smooth is
the highest-value UX change available.

## Proposed scope
- Persist the parsed CV text in `chrome.storage.session` (cleared when the browser closes, ideal
  for CV content) or `chrome.storage.local` if it should survive restarts. Decide based on the
  privacy tradeoff and document the choice — a CV is personal data, and keeping it only for the
  session is the safer default.
- On panel load, restore the CV and show the correct state ("CV added ✓ — cv.pdf") rather than a
  blank upload prompt.
- Add a "Remove CV" / "Replace" action, and clear the stored value when removed.
- Show a small preview (first ~200 characters or a character count) so the user can confirm the
  right text was extracted — this also makes the scanned-PDF failure obvious (EXT-001).
- Ensure the stored value is cleared on `chrome.storage.session` access level appropriately, and
  never write it anywhere remotely.
- Fix the `cvInput.value` reset so re-selecting the same file works.

## Acceptance criteria
- [ ] Closing and reopening the side panel keeps the CV loaded.
- [ ] The panel shows which CV is loaded, with a way to replace or remove it.
- [ ] A preview or character count of the extracted text is visible.
- [ ] Removing the CV clears it from storage.
- [ ] Re-uploading after a failure, including the same filename, works.
- [ ] The storage choice and its privacy reasoning are documented.

## Notes
Session-only storage is the right default: it makes the repeated-analysis flow fast without leaving
CV text on disk indefinitely. State that reasoning explicitly rather than leaving it implicit.
