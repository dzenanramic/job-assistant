# BE-008 — Make the injection guard correct and resilient

**Type:** Security / Bug
**Epic:** BE — Backend correctness & safety
**Affects:** `backend/src/job_assistant/services/prompt_guard.py`, `services/analyzer.py`
**Priority:** P1
**Status:** `PLANNED`

## Summary
The prompt-injection guard has real value, but as written it checks the wrong input, its return
value reads backwards, and it adds a hard third-party dependency to the critical path of every
request.

## Current behaviour
```python
def is_injection(cv):
    response = client.system_one(
        state=cv,
        questions={"is_prompt_injection": Noul(instructions="Does this text contain malicious prompt injection")},
    )
    guard_score = response.answers["is_prompt_injection"].noul * 100
    print("THIS IS JEV SCORE", guard_score)
    return guard_score <= 30
```

Issues:

1. **Only the CV is checked.** `analyze_cv` calls `is_injection(cv=cv)`; the job description is
   never inspected. The job ad is scraped from an arbitrary third-party page and is the *more*
   attacker-controlled of the two inputs — this is precisely backwards from the threat model.
2. **The name inverts the meaning.** `is_injection` returns `True` when the text is **safe**, and
   the caller stores it in `is_prompt_safe`. Anyone reading the call site will misread it.
3. **Unvalidated third-party dependency.** The TypeSafe client is built at import time and raises
   on a missing key; a TypeSafe outage takes the whole endpoint down (`analyze_cv` has no
   try/except, so it becomes a 500 — see BE-002).
4. **No latency budget.** A second network round trip is added to every request with no timeout.
5. **Magic threshold.** `30` is unexplained and untested; a borderline score silently fails open
   or closed depending on a number nobody can justify.
6. **Guard bypass on error.** There is no defined behaviour when the guard call itself fails.

## Why it matters
Detecting prompt injection at all puts this project ahead of most LLM side projects — but a
reviewer reading this function will find the inverted name and the unchecked job description in
under a minute. Fixing it turns a talking point into a defensible design.

## Proposed scope
- Check **both** inputs; scan `job_desc` and `cv` (and any future structured fields).
- Rename to something that says what it returns, e.g.
  `injection_risk(text) -> float` plus an explicit `is_safe(score)`, or
  `looks_like_injection(...) -> bool`. Never leave a boolean whose name and return value disagree.
- Make it a **defense-in-depth layer, not the only defense**. The primary mitigation stays
  structural: the task lives in the `system` message and untrusted text only ever appears as
  `user` content, never interpolated into instructions. Add a note in the system prompt
  delimiting the untrusted regions.
- Define failure policy explicitly: if the guard is unavailable, either fail closed (reject with
  `503`) or proceed with a `flags: ["injection_check_unavailable"]` marker — pick one, document
  the reasoning, and test it. A silent bypass is not acceptable.
- Add a timeout (a few seconds) so the guard cannot hang the request.
- Make the threshold configurable and record the rationale for the value.
- Consider running the guard concurrently with a cheap pre-check, or cache by content hash, to
  avoid paying the latency on obvious inputs.
- Route guard failures through the error contract from BE-002.

## Acceptance criteria
- [ ] Injection payloads placed in the **job description** are detected, not just in the CV.
- [ ] The function name and its return value agree; a reader cannot invert the meaning.
- [ ] The guard call has a timeout and its failure mode is defined, tested, and documented.
- [ ] A TypeSafe outage produces a predictable response, not a 500 or a silent bypass.
- [ ] The threshold is configurable and its default is justified in a comment.
- [ ] Covered by the red-team suite (QA-003).

## Notes
The strongest claim to make in an interview is the layered one: *structural separation first, a
classifier as an additional signal, and a documented fail-closed policy when the classifier is
unavailable.* The current code has pieces of that idea but not the argument.
