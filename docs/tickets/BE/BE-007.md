# BE-007 — Config and secrets hygiene

**Type:** Security / Chore
**Epic:** BE — Backend correctness & safety
**Affects:** `backend/`
**Priority:** P1
**Status:** `PLANNED`

## Summary
Configuration is read from a `.env` file that sits **inside the source package**, is loaded with a
bare `load_dotenv()` that depends on the current working directory, and has no documented schema.
There is no `.env.example` for the FastAPI backend, so a new clone cannot be configured from the
repo alone.

## Current behaviour
```python
# services/deepseek_client.py and services/prompt_guard.py, both
load_dotenv()
DEEPSEEK_API_KEY = os.getenv("DEEPSEEK_API_KEY")
client = OpenAI(api_key=DEEPSEEK_API_KEY, base_url="https://api.deepseek.com")
```

- The real file is at `backend/src/job_assistant/.env` — inside the package, not at `backend/.env`.
- `load_dotenv()` resolves relative to the CWD, so behaviour depends on where the server is started.
- The OpenAI client is constructed **at import time**. A missing key therefore makes the module
  fail to import rather than fail with a clear startup message.
- `prompt_guard.py` constructs a TypeSafe client the same way, and that one *raises at import*
  when the key is absent — imported code cannot even be unit tested without a dummy key.
- `.gitignore` does contain `.env`, and `git ls-files` confirms only `backend/.env.example` was
  ever tracked. **Verify this yourself** and rotate both keys if any real key ever reached a
  remote — assume compromise if unsure.

## Why it matters
Secrets handling is a standard interview probe, and "the app won't import without a key" makes the
project harder to test and impossible to contribute to. A committed key is an instant red flag.

## Proposed scope
- Move the env file to `backend/.env` (outside `src/`), and add `backend/.env.example` listing
  every variable with placeholder values and a comment each.
- Fail fast with a readable message at **startup** (not import) when a required variable is
  missing — e.g. a Pydantic `BaseSettings` class that validates on app creation.
- Load configuration once and inject it, instead of `os.getenv` scattered across modules.
- Make model name, base URL, timeouts, log level, CORS origins, size caps, and rate limits
  configurable.
- Add a startup check that logs which configuration is active, with secrets redacted.
- Update `.gitignore` to also cover `.env.*` except `.env.example`, and keep ignoring
  `__pycache__/` (BE-001).
- Document every variable in `backend/README.md` (DOC-001).

## Acceptance criteria
- [ ] `backend/.env.example` exists and lists every required variable with a description.
- [ ] No real key exists anywhere in the package directory.
- [ ] Starting without `DEEPSEEK_API_KEY` prints one clear error listing the missing variable.
- [ ] Modules can be imported in a test process with no environment variables set.
- [ ] `git log --all -p -- '*env*' | grep -i 'sk-'` finds no real key (run it and record the result).
- [ ] Model name, timeouts, and limits are configurable without editing code.

## Notes
If the repository has ever been pushed with a real key, rotate it — removal from history is not
enough, and the key must be considered public.
