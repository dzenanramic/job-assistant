# BE-003 — Remove debug `print()` calls; add structured logging

**Type:** Chore / Observability
**Epic:** BE — Backend correctness & safety
**Affects:** `backend/src/job_assistant/`
**Priority:** P0 (trivial to fix, loud signal)
**Status:** `PLANNED`

## Summary
Debug `print()` statements are scattered through the request path. They leak the user's full CV and
job text to stdout and make the code read as work-in-progress.

## Current behaviour
```python
# analyzer.py
print(job_desc, cv)                                    # prints the user's entire CV
print("TIP 1", type(result))
print("THIS IS RESULT", result)
print("TIP 2", type(result))

# prompt_guard.py
print("THIS IS JEV SCORE", guard_score)
```

Consequences beyond untidiness:

- **Privacy:** the whole CV is written to stdout on every request. If this is ever deployed, CVs
  land in log aggregation in plain text. That is personal data.
- **No severity, no timestamp, no request id.** These lines are unusable for actual diagnosis.
- Debug markers like `TIP 1` / `THIS IS JEV SCORE` are the first thing a code reviewer notices.

## Why it matters
Cheap to fix, disproportionately visible. "Uses structured logging, and does not log PII" is a
concrete, checkable claim on a CV; leftover `print()`s are the opposite.

## Proposed scope
- Delete all debug `print()` calls.
- Introduce the stdlib `logging` module with a JSON (or key/value) formatter including timestamp,
  level, logger name, and request id (from BE-010).
- Log **metadata, not content**: character counts, model name, token usage, latency, outcome.
  Never log raw `cv` or `job_desc`.
- Set log level from configuration (BE-007); default `INFO` in dev, `WARNING` in prod.
- Add a startup log line and a shutdown log line.
- Add a test asserting the CV text does not appear in captured log output.

## Acceptance criteria
- [ ] `grep -rn "print(" backend/src/` returns nothing.
- [ ] Logs are machine-parseable (JSON or consistent key/value) with timestamp and level.
- [ ] A request that includes a distinctive CV string does **not** put that string in the logs.
- [ ] Log level is configurable via environment variable.
- [ ] A test asserts CV/job content is absent from log records.
