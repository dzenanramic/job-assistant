# BE-005 — Rate limiting and a daily spend cap

**Type:** Security / Cost control
**Epic:** BE — Backend correctness & safety
**Affects:** `backend/src/job_assistant/main.py`
**Priority:** P1
**Status:** `PLANNED`

## Summary
`POST /jobs` is open, unauthenticated, and unlimited. Every call spends real money on DeepSeek and
TypeSafe. Nothing stops one script from draining the account.

## Current behaviour
There is no throttling middleware, no per-client accounting, and no spending ceiling. CORS is `*`
(BE-006), so any web page can call the endpoint from a visitor's browser.

Two separate problems, often conflated:

1. **Burst protection** — one client firing hundreds of requests per minute.
2. **Budget protection** — total spend per day, regardless of how it is spread across clients.

Fixing only the first still allows a slow, distributed drain.

## Why it matters
"I put rate limiting and a spend cap on an LLM endpoint" is a specific, credible engineering claim
that most portfolio projects cannot make. It also protects you personally: a public demo URL
without a cap can produce a real bill.

## Proposed scope
- Add per-client rate limiting (e.g. `slowapi`, which is the FastAPI-idiomatic wrapper over
  `limits`): a short window (`20/minute`) and a daily window (`200/day`), keyed by client IP.
- Return `429` with a `Retry-After` header and the standard error contract from BE-002.
- Add an in-process daily token/cost counter that refuses further model calls once a configured
  budget is hit, returning `503` with a clear "daily budget reached" message.
- Track token usage from the DeepSeek response (`usage.total_tokens`) and expose it (BE-010).
- Make every limit configurable via environment variables (BE-007).
- Document the chosen limits and the reasoning in the README.
- Note honestly that IP-keyed limits are per-process and reset on restart — say so in the ticket
  and the README rather than implying they are durable (durable limiting belongs with MOB-004's
  auth work, where clients can be identified by key instead of IP).

## Acceptance criteria
- [ ] Exceeding the per-minute limit returns `429` with a `Retry-After` header.
- [ ] Exceeding the daily limit returns `429` regardless of request spacing.
- [ ] Once the configured token/cost budget is exhausted, no further DeepSeek call is made.
- [ ] Limits are configurable without a code change.
- [ ] Tests cover both the 429 contract and the budget short-circuit.
- [ ] README states the limits and the single-process caveat.

## Notes
Order matters: BE-004 (size caps) reduces the cost of a single request, BE-005 bounds the number of
requests, and MOB-004 replaces IP identity with real API-key identity. Together they are the
"abuse handling" story worth telling in an interview.
