# BE-004 — Request validation and size limits

**Type:** Security / Backend feature
**Epic:** BE — Backend correctness & safety
**Affects:** `backend/src/job_assistant/schemas/schemas.py`, `api/v1/analyze.py`
**Priority:** P1
**Status:** `PLANNED`

## Summary
The endpoint accepts any JSON body with any size. There are no length caps, no emptiness checks,
and no rejection of unexpected fields — and every request that gets through is billed to the
DeepSeek account.

## Current behaviour
```python
class JobContext(BaseModel):
    text: str
    cvText: str
```
Two unconstrained strings. Consequences:

- A multi-megabyte `text` is passed straight to DeepSeek, inflating cost and risking a context
  overflow error.
- `{"text": "", "cvText": ""}` is accepted and billed, producing a meaningless analysis.
- Extra keys are silently ignored rather than reported.
- The camelCase `cvText` field is inconsistent with the snake_case `text` field in the same model.
- No global request-body size limit, so a huge payload is fully read before validation runs.

## Why it matters
Input validation is the most commonly probed topic in backend interviews, and here it doubles as
cost control. A reviewer will send an empty body and a 10 MB body within the first five minutes.

## Proposed scope
- Constrain the model:
  - `text`: `min_length=20`, `max_length=60_000`
  - `cvText`: `min_length=50`, `max_length=60_000`
  - `model_config = ConfigDict(extra="forbid")` so unknown keys are a 400.
- Reject bodies that are whitespace-only (a `field_validator` that strips and re-checks length).
- Rename `cvText` → `cv_text` for consistency, and keep `cvText` as a deprecated alias accepting
  the old name during the transition (`AliasChoices`), so the shipped extension keeps working.
- Add a pre-model token/character estimate guard in the service; refuse with `413` before any
  paid call when over budget.
- Enforce a body-size ceiling at the ASGI layer so oversized payloads are rejected before parsing.
- Return `422`/`413` with a message naming the offending field and the limit.

## Acceptance criteria
- [ ] Empty `text` or `cvText` returns `422` and never reaches the model.
- [ ] A 5 MB `text` returns `413` and never reaches the model.
- [ ] An extra body key (`{"text": "...", "cvText": "...", "admin": true}`) returns `422`.
- [ ] The extension's current `cvText` payload still works (backward compatible).
- [ ] A test asserts the model client is not called for rejected requests (QA-001).
- [ ] Documented limits exist in the README.

## Notes
The 60k cap is a placeholder — set it from the real DeepSeek context window minus the prompt
overhead, and record the arithmetic in a comment so the number is justifiable in an interview.
