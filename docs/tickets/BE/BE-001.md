# BE-001 — Fix import paths so the app actually boots

**Type:** Bug (blocker)
**Epic:** BE — Backend correctness & safety
**Affects:** `backend/src/job_assistant/`
**Priority:** P0 (blocks everything)
**Status:** `PLANNED`

## Summary
The backend cannot start. Running `uvicorn` against the app raises `ModuleNotFoundError` before any
request is ever served.

## Current behaviour
The package lives at `backend/src/job_assistant/`, but every module imports as if
`src/job_assistant/` were the project root:

```python
# backend/src/job_assistant/main.py
from api.v1.analyze import router as analyze_router   # no such top-level module

# backend/src/job_assistant/api/v1/analyze.py
from services.analyzer import analyze_cv              # no such top-level module
from models.schemas import AnalysisResponse, JobContext

# backend/src/job_assistant/services/analyzer.py
from .prompt_guard import is_injection                # relative — inconsistent with the above
from .deepseek_client import ai_response
```

Verified:

```
$ python -c "import job_assistant.main"
ModuleNotFoundError: No module named 'api'
```

A second, independent failure hides behind the first: `analyze.py` imports from `models.schemas`,
but **no `models/` package exists** — the file is at `schemas/schemas.py`. Fixing the first
`ModuleNotFoundError` alone will not boot the app.

## Why it matters
Nothing else in this backlog can be tested, demoed, or reviewed until the server runs. It also
means the project as committed has never been started from a clean checkout.

## Proposed scope
- Convert all intra-package imports to absolute imports rooted at `job_assistant`:
  `from job_assistant.services.analyzer import analyze_cv`, and so on inside `analyzer.py` too.
- Fix the `models.schemas` reference to point at the real location (or rename the `schemas`
  package to `models` — pick one; ARCH-001 covers the wider layout decision).
- Add `__init__.py` to `api/v1/` if missing, so the package is importable without relying on
  implicit namespace packages.
- Add `[tool.uv]` / setuptools package configuration in `pyproject.toml` so `uv sync` installs the
  package and `uv run uvicorn job_assistant.main:app` works from `backend/`.
- Record the exact run command in `backend/README.md` (see DOC-001).
- Delete the `__pycache__/*.pyc` files currently in the tree; they are committed build artifacts.

## Acceptance criteria
- [ ] `cd backend && uv run uvicorn job_assistant.main:app --reload` starts with no import errors.
- [ ] `curl localhost:8000/` returns `{"message": "Hello World"}`.
- [ ] No relative import and no bare top-level import remains under `job_assistant/`.
- [ ] `__pycache__` is git-ignored and untracked.
- [ ] `backend/README.md` documents the working run command.

## Notes
Do this first, then verify every later ticket against a running server. The `__pycache__`
directories in the tree suggest the app was last run with the CWD set to `src/job_assistant/`,
which is why this was never caught.
