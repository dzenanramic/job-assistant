# DOC-001 — Rewrite the READMEs to match reality

**Type:** Documentation
**Epic:** DOC — Documentation
**Affects:** `README.md`, `backend/README.md`
**Priority:** P0 (highest visibility per unit of effort)
**Status:** `PLANNED`

## Summary
The root README describes a project that no longer exists, and `backend/README.md` is an empty
file. For a portfolio project this is the single most damaging gap: the README is what a reviewer
reads before deciding whether to look at the code at all.

## Current behaviour
`README.md` states:

- *"Chrome ekstenzija + **NestJS** backend"* — the backend is **FastAPI/Python**. NestJS was
  replaced; the README was not.
- *"`backend/.env.example` — kopiraj u `.env`"* — that file does not exist for the FastAPI backend.
- *"`extension/` — Chrome extension (nepromijenjena)"* — it has been changed substantially (side
  panel, PDF parsing, results UI, three sites).
- *"Backend API: `http://localhost:3000/jobs`"* and *"port 3000"* — the extension calls
  `http://127.0.0.1:8000/jobs`. Both the port and the host differ.
- *"`npm install` / `npm run start:dev`"* — those are Node commands for a Python backend that uses
  `uv`.
- The structure tree lists `backend/src/` as "izvorni kod (nepromijenjen)".

`backend/README.md` is 0 bytes.

Additional mismatch a reviewer will hit immediately: the extension is titled **"Job Finder
Assistant"** in `manifest.json` and "Job Assistant" everywhere else.

## Why it matters
A README that describes a different tech stack reads as either careless or copy-pasted — and it
undercuts the parts of the project that are genuinely good. This is also the cheapest fix in the
entire backlog relative to its impact.

## Proposed scope
Rewrite the root `README.md` (in **English**, since the rest of the codebase and the UI are English
— or Bosnian consistently, but pick one and say so):

1. **One-sentence pitch**, then a short "what it does" paragraph.
2. **Screenshot or GIF** of the side panel showing a real analysis. This is the highest-value
   single addition to the README.
3. **Architecture diagram** — extension → backend → DeepSeek/TypeSafe, showing where the CV is
   parsed (in the browser) and where the guard runs (backend).
4. **Quick start** that actually works: prerequisites (Chrome, `uv`), backend setup with the
   correct `uv` commands, `cp .env.example .env`, the `uvicorn` run command with the right port,
   extension load steps, and how to point the extension at the backend.
5. **Environment variables** table — every variable, what it is for, whether it is required.
6. **API reference** — the endpoint, request/response shapes, error codes, link to `/docs`
   (BE-011).
7. **Supported sites** — list them plainly, including that other sites are unsupported or
   best-effort (EXT-004).
8. **Testing** — how to run the suites (QA-001, QA-004) and the CI badge (QA-002).
9. **Security notes** — what is defended (prompt injection, input caps, XSS) and, importantly,
   **what is not** (no auth, in-process rate limits, no persistence). Honest scope beats
   overselling.
10. **Roadmap** — link to `docs/tickets/`, summarising P0/P1 items.

Also:
- Fill in `backend/README.md` with backend-specific setup, env vars, run command, and test command.
- Fix the extension name mismatch so `manifest.json`, the UI, and the README agree.
- Add a licence file if the repo is public (currently none).

## Acceptance criteria
- [ ] Following the README from a clean clone gets a working analysis, with no undocumented steps.
- [ ] No mention of NestJS, TypeScript, port 3000, or files that do not exist.
- [ ] A screenshot or GIF of the working extension is embedded.
- [ ] Architecture diagram is present.
- [ ] Every environment variable is documented.
- [ ] Security section states limitations as well as defenses.
- [ ] `backend/README.md` is not empty and its commands work.
- [ ] Product name is consistent across manifest, UI, and README.
- [ ] The documented backend URL matches what `api.js` actually calls.

## Notes
Do this **after** BE-001 (so the documented run command actually works) but **before** the larger
